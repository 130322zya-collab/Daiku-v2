# ✅ 確認係（Reviewer）ガイドライン

## 役割
実装係の成果物を **客観的な目線でチェック** する。
バグ・品質問題・仕様漏れを見つけ、OKなら合格、NGなら具体的なフィードバックを返す。

---

## レビューの観点

### 1. 正確性（動くか）
- [ ] 実装が仕様通りか
- [ ] 明らかなバグや論理エラーがないか
- [ ] エッジケースで壊れないか（空データ、長い文字列など）

### 2. 品質（良いコードか）
- [ ] 読みやすいか（変数名・関数名が意味を表しているか）
- [ ] 重複したコードがないか
- [ ] 不要なコードが残っていないか

### 3. セキュリティ（安全か）
- [ ] XSSリスクのある `dangerouslySetInnerHTML` を使っていないか
- [ ] ユーザー入力をそのまま使っていないか

### 4. 一貫性（既存コードと合っているか）
- [ ] スタイルが既存コードに合っているか
- [ ] 日本語UIになっているか
- [ ] 既存コンポーネント（`Badge`、`Modal`、`FormField` など）を再利用しているか

---

## フィードバックの書き方

### OK の場合
```
✅ レビュー合格
- 仕様通りに実装されています
- コードも読みやすく問題なし
→ コミット・プッシュOK
```

### NG の場合
```
❌ 要修正
- [重大] ○○のバグがあります → ファイル名:行番号
- [軽微] △△の変数名が分かりにくい → ○○に変更推奨
→ 実装係に差し戻し
```

重大度の基準：
- **重大**: ユーザーに影響するバグ・セキュリティ問題
- **軽微**: コード品質・スタイルの問題

---

## チェックリスト（レビュー完了の判断基準）

- [ ] 全変更ファイルを読んだか
- [ ] 仕様の完了条件を満たしているか
- [ ] 重大な問題はないか
- [ ] フィードバックは具体的か（「なおして」ではなく「○行目の△を□に変更」）
