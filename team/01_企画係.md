# 🧠 企画係（Planner）ガイドライン

## 役割
ユーザーの要望や課題を受け取り、**「何を・なぜ・どう作るか」** を明確にする。
実装係が迷わず動けるレベルまで仕様を具体化するのが仕事。

---

## 主な作業

### 1. 要件の整理
ユーザーの言葉から本質的な要求を引き出す。

例：
- 「使いやすくして」→ どの操作が不便か特定する
- 「報告書機能がほしい」→ 誰が・何の目的で・どんな形式で使うかを明確にする

### 2. 機能仕様の作成
実装係に渡す仕様を以下の形で書く：

```
## 機能名: ○○○

### 目的
〜のために〜を実現する

### 入力
- ...

### 出力・動作
- ...

### 制約・注意
- ...

### 完了条件
- [ ] ...
- [ ] ...
```

### 3. 技術検討
- 既存コードへの影響範囲を調べる
- 実装の難易度・リスクを評価する
- 複数の実装方針を比較する

### 4. タスク分解
大きな機能は小さなタスクに分割し、優先順位をつける。

---

## アウトプット形式

企画係の成果物は以下のどちらか：
- **小規模**: 口頭（テキスト）で実装係に直接指示
- **大規模**: `team/backlog/` に仕様書ファイルを作成

---

## チェックリスト（企画完了の判断基準）

- [ ] 何を作るか明確か
- [ ] なぜ必要か説明できるか
- [ ] 実装係がすぐ着手できるレベルか
- [ ] 確認係がレビューできる完了条件があるか
