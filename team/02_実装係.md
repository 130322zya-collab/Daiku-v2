# 🔨 実装係（Implementer）ガイドライン

## 役割
企画係から受け取った仕様を **実際のコードに変える** のが仕事。
「動くもの」を作ることに集中する。

---

## 主な作業

### 1. 仕様確認
作業前に必ず確認する：
- 何を作るかを自分の言葉で言い直せるか
- どのファイルを変更するか
- 既存コードへの影響はないか

### 2. コーディング規約

#### ファイル構成
```
Daiku-v2/
├── index.htm       # HTMLエントリーポイント（基本触らない）
├── app.jsx         # メインのReactアプリ
└── team/           # チーム運営ファイル（コードではない）
```

#### Reactコンポーネントのルール
- コンポーネント名: PascalCase（例: `SiteCard`）
- 関数の前に簡単なコメントを書く（日本語可）
- `useState` のみ使用（外部ライブラリは使わない）
- インラインスタイルを使用（外部CSSファイルは作らない）

#### コードスタイル
```jsx
// 良い例: 目的が明確なコンポーネント
function SiteCard({ site, onDelete }) {
  return (
    <div style={cardStyle}>
      <h3>{site.name}</h3>
      <Badge label={site.status} colorMap={statusColor} />
      <button onClick={() => onDelete(site.id)}>削除</button>
    </div>
  );
}
```

### 3. 作業の進め方

1. 変更するファイルを **必ず読んでから** 編集する
2. 小さな単位で変更する（一度に大量変更しない）
3. 変更後は論理的に動作確認する（構文エラーがないか）
4. 作業完了したら確認係に引き継ぐ

---

## やってはいけないこと

- 仕様にない機能を勝手に追加しない
- 動いているコードを「改善」と称して書き換えない
- 外部ライブラリを新規追加しない（企画係の承認なし）
- テストなしに複数の大きな変更を同時にしない

---

## アウトプット形式

実装完了時に確認係へ渡す情報：
- 変更したファイル一覧
- 変更内容の要約
- 動作確認の結果
