# チーム作業のワークフロー例

実際の作業がどう流れるか、具体例で説明します。

---

## 例1: 新機能追加「写真添付機能がほしい」

```
ユーザー: 「現場の写真を登録できるようにして」
              ↓
🧠 企画係が動く
  - 「写真」の意味を確認（URL？ファイル？）
  - 現状のデータ構造を調べる
  - 仕様を決める:「URLを入力してサムネイル表示する」
              ↓
🔨 実装係が動く
  - SiteCard コンポーネントに photo フィールド追加
  - 現場追加フォームに URL 入力欄を追加
  - サムネイル表示コンポーネントを作成
              ↓
✅ 確認係が動く
  - 仕様通りに動くか確認
  - URL が空の場合にエラーが出ないか確認
  - レビュー合格 → コミット
```

---

## 例2: バグ修正「削除ボタンが効かない」

```
ユーザー: 「タスクを削除しても消えない」
              ↓
🔨 実装係がまず調べる（小さいバグは企画不要）
  - app.jsx の handleDelete 関数を確認
  - バグを特定して修正
              ↓
✅ 確認係が動く
  - 修正内容が正しいか確認
  - 他の削除機能（現場・作業員）に同じバグがないか確認
  - レビュー合格 → コミット
```

---

## 例3: 改善提案「もっとカラフルにして」

```
ユーザー: 「もっとデザインをよくして」
              ↓
🧠 企画係が動く
  - 具体的に何が課題か分析
  - 改善案を3つ提案してユーザーに選ばせる
  - ユーザーが「ヘッダーの色を変えて」と決定
              ↓
🔨 実装係が動く
  - ヘッダーのスタイルを修正
              ↓
✅ 確認係が動く
  - 変更箇所が意図通りか確認
  - 他のスタイルへの影響がないか確認
```

## よくある質問

**Q: 誰がどの係を担当するの？**
A: Claude が状況に応じて自動的に係を切り替えます。ユーザーは普通に「〜して」と言えばOKです。

**Q: 人間のチームメンバーは？**
A: 今のところ Claude が全係を担当します。将来的にメンバーが増えたらこのガイドラインに従って役割分担します。

**Q: 急いでいるときは？**
A: 「急いで」「すぐに」と言えば、企画フェーズを省略して実装係から始めます。ただし確認係は必ず通します。
